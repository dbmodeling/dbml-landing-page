You leave DB Modeling with what you need: DDL ready for your database, an image for the presentation or a Mermaid diagram for the README. The example below shows the same schema as DBML, SQL (PostgreSQL) and Mermaid.

## What you can export

| Format | File | Desktop | Web | VS Code | CLI |
|---|---|---|---|---|---|
| SQL PostgreSQL | `.sql` | Yes | Yes | Yes | `dbml export --dialect postgres` |
| SQL MySQL | `.sql` | Yes | Yes | Yes | `dbml export --dialect mysql` |
| SQL SQLite | `.sql` | Yes | Yes | Yes | `dbml export --dialect sqlite` |
| SQL SQL Server | `.sql` | Yes | Yes | Yes | `dbml export --dialect sqlserver` |
| SQL Oracle | `.sql` | Yes | Yes | Yes | `dbml export --dialect oracle` |
| Mermaid `erDiagram` | `.mmd` | Yes | Yes | Yes | Inside `dbml docs --format md` |
| PNG, JPEG | `.png`, `.jpg` | Yes | Yes | Yes | No |
| SVG | `.svg` | Yes | Yes | Yes | No |
| HTML or Markdown documentation | `.html`, `.md` | Yes | Yes | Yes | `dbml docs` (see [Generate documentation](../guias/gerar-documentacao)) |
| DBML | `.dbml` | No | Yes | No | No (the file is already DBML) |

Oracle exports DDL normally. What does not exist yet for Oracle is the direct database connection (see [Connect to a database](../guias/conectar-banco)).

## Prerequisites

- A schema with no errors in the **Problems** panel. A SQL export with a DBML error fails.
- For images, the diagram visible on the canvas.
- For the CLI, the `dbml` binary (see [Installation](../comecar/instalacao)).

## Steps

### SQL in the app

1. Open the **Export code** menu in the toolbar, or use the palette (<Atalho acao="OpenPalette" />) and type `Export code`.
2. Pick the dialect:

   | Palette command |
   |---|
   | **Export code: PostgreSQL (.sql)** |
   | **Export code: MySQL (.sql)** |
   | **Export code: SQLite (.sql)** |
   | **Export code: SQL Server (.sql)** |
   | **Export code: Oracle (.sql)** |

3. Choose where to save. On the Desktop, the suggested name follows the schema and the dialect, for example `loja.postgres.sql`.

The SQL exports have no keyboard shortcut. They live in the palette and in the menu.

### Mermaid in the app

1. Open **Export code** and pick **Export code: Mermaid erDiagram (.mmd)**.
2. Paste the content of the `.mmd` into a ` ```mermaid ` block in your README. GitHub and GitLab render the diagram.

Mermaid only accepts letters, numbers and `_` in names. DB Modeling replaces any other character with `_` and, if two names end up equal, adds a suffix and notes the change in a `%%` comment.

### Image in the app

1. Open the **Export image** menu, or use the palette.
2. Pick the format:
   - **Export image: PNG**: raster at 2× resolution.
   - **Export image: JPEG**: raster with a solid background.
   - **Export image: SVG vector**: scalable and editable in Figma, Inkscape and similar tools.
3. Choose where to save.

Very large diagrams are rasterized at a smaller scale to avoid running out of memory. If you need full resolution, export as SVG.

### Export the DBML (Web only)

Use the **Export DBML** button in the toolbar, or **Export DBML (.dbml)** in the **File** menu. This downloads a copy of the current text. This command exists only on the Web.

### SQL in the CLI

```bash
dbml export schema.dbml --format sql --dialect postgres -o schema.sql
```

- `--dialect` accepts `postgres`, `mysql`, `sqlite`, `sqlserver` and `oracle`. Aliases: `pg`, `postgresql`, `sqlite3`, `mssql`, `tsql` and `ora`.
- Without `-o`, the SQL goes to standard output. Use it in pipes: `dbml export schema.dbml --dialect mysql | mysql loja`.
- With `-o`, the command refuses to overwrite an existing file. Use `--force` to allow it.

### Mermaid in the CLI

The CLI has no `--format mermaid`. Mermaid comes inside the Markdown documentation:

```bash
dbml docs schema.dbml --format md -o docs/
```

The generated `README.md` includes an `erDiagram` block. See [Generate documentation](../guias/gerar-documentacao).

## Notes about the generated SQL

- The file header names the dialect: `-- Generated by DB Modeling (postgres)`.
- Enums: `CREATE TYPE ... AS ENUM` on PostgreSQL, `ENUM(...)` on the column on MySQL, and `CHECK (... IN (...))` on SQLite, SQL Server and Oracle.
- Notes: `COMMENT ON` on PostgreSQL and Oracle, `COMMENT` on the table and column on MySQL. SQLite and SQL Server do not receive the notes.
- SQLite does not accept schemas (`auth.users`). The export warns you and stops.

## If something goes wrong

| Message | Likely cause | What to do |
|---|---|---|
| `Check the DBML before exporting SQL: <detail>` | The DBML has an error. | Open **Problems** and fix it. |
| `SQLite does not support the schema <name> in this export. Choose another dialect.` | A table uses a schema (`auth.users`). | Export in another dialect, or drop the schema from the name. In the CLI: ``Error: SQLite export does not support schema `auth` ``. |
| `Choose another dialect for SQL export.` | The chosen dialect is not supported. | Use one of the five dialects. |
| `Could not generate <format>. Try exporting as SVG.` (Web) / `Try exporting as SVG.` (Desktop) | Generating the raster image failed. | Export as SVG, which does not depend on rasterization. |
| `Could not export <format>. Try a different name or folder.` (Web) | Writing failed. | Use another name or folder. |
| `Failed to export <format>: <detail>` (Desktop) / `Export failed: <detail>` and `SQL export failed: <detail>` (Web) | Generic error. | Read the detail in the message. |
| `The file is in use. Close it in the other app or export with a different name.` | The destination file is open in another program. | Close it or change the name. |
| `Permission denied. Choose a different folder.` | Folder without permission. | Choose another folder. |
| `The disk is full. Free some space or choose a different folder.` | No space left. | Free some space. |
| `Could not open the save dialog. Try exporting again.` | The system dialog did not open. | Try again. |
| `Error: invalid DBML: <detail>` (CLI) | The `.dbml` file has an error. | Fix the indicated spot. |
| `output file ... already exists (pass --force to overwrite)` (CLI) | The destination already exists. | Use `--force` or another name. |
| `error: invalid value 'foo' for '--dialect <DIALECT>'` (CLI) | Unknown dialect. | Use `[possible values: postgres, mysql, sqlite, sqlserver, oracle]`. |
