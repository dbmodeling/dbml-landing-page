Você sai do DB Modeling com o que precisa: DDL pronto para o seu banco, uma imagem para a apresentação ou um diagrama Mermaid para o README. O exemplo abaixo mostra o mesmo esquema como DBML, SQL (PostgreSQL) e Mermaid.

## O que dá para exportar

| Formato | Arquivo | Desktop | Web | VS Code | CLI |
|---|---|---|---|---|---|
| SQL PostgreSQL | `.sql` | Sim | Sim | Sim | `dbml export --dialect postgres` |
| SQL MySQL | `.sql` | Sim | Sim | Sim | `dbml export --dialect mysql` |
| SQL SQLite | `.sql` | Sim | Sim | Sim | `dbml export --dialect sqlite` |
| SQL SQL Server | `.sql` | Sim | Sim | Sim | `dbml export --dialect sqlserver` |
| SQL Oracle | `.sql` | Sim | Sim | Sim | `dbml export --dialect oracle` |
| Mermaid `erDiagram` | `.mmd` | Sim | Sim | Sim | Dentro de `dbml docs --format md` |
| PNG, JPEG | `.png`, `.jpg` | Sim | Sim | Sim | Não |
| SVG | `.svg` | Sim | Sim | Sim | Não |
| Documentação HTML ou Markdown | `.html`, `.md` | Sim | Sim | Sim | `dbml docs` (veja [Gerar documentação](../guias/gerar-documentacao)) |
| DBML | `.dbml` | Não | Sim | Não | Não (o arquivo já é DBML) |

Oracle exporta DDL normalmente. O que ainda não existe para Oracle é a conexão direta ao banco (veja [Conectar a um banco](../guias/conectar-banco)).

## Pré-requisitos

- Um esquema sem erros no painel **Problemas**. Uma exportação de SQL com erro de DBML falha.
- Para imagens, o diagrama visível no canvas.
- Para a CLI, o binário `dbml` (veja [Instalação](../comecar/instalacao)).

## Passos

### SQL pelo app

1. Abra o menu **Exportar código** na barra de ferramentas, ou use a paleta (<Atalho acao="OpenPalette" />) e digite `Exportar código`.
2. Escolha o dialeto:

   | Comando da paleta |
   |---|
   | **Exportar código: PostgreSQL (.sql)** |
   | **Exportar código: MySQL (.sql)** |
   | **Exportar código: SQLite (.sql)** |
   | **Exportar código: SQL Server (.sql)** |
   | **Exportar código: Oracle (.sql)** |

3. Escolha onde salvar. No Desktop, o nome sugerido segue o esquema e o dialeto, por exemplo `loja.postgres.sql`.

As exportações de SQL não têm atalho de teclado. Elas ficam na paleta e no menu.

### Mermaid pelo app

1. Abra **Exportar código** e escolha **Exportar código: Mermaid erDiagram (.mmd)**.
2. Cole o conteúdo do `.mmd` em um bloco ` ```mermaid ` do seu README. O GitHub e o GitLab renderizam o diagrama.

O Mermaid só aceita letras, números e `_` nos nomes. O DB Modeling troca qualquer outro caractere por `_` e, se dois nomes ficarem iguais, acrescenta um sufixo e anota a troca em um comentário `%%`.

### Imagem pelo app

1. Abra o menu **Exportar imagem**, ou use a paleta.
2. Escolha o formato:
   - **Exportar imagem: PNG**: raster em resolução 2×.
   - **Exportar imagem: JPEG**: raster com fundo sólido.
   - **Exportar imagem: SVG vetorial**: escalável e editável em Figma, Inkscape e similares.
3. Escolha onde salvar.

Diagramas muito grandes são rasterizados em escala menor para não estourar a memória. Se precisar de resolução total, exporte em SVG.

<Modalidade so="web">
### Exportar o DBML (só Web)

Use o botão **Exportar DBML** na barra de ferramentas, ou **Exportar DBML (.dbml)** no menu **Arquivo**. Isso baixa uma cópia do texto atual. Esse comando só existe na Web.
</Modalidade>

### SQL pela CLI

```bash
dbml export schema.dbml --format sql --dialect postgres -o schema.sql
```

- `--dialect` aceita `postgres`, `mysql`, `sqlite`, `sqlserver` e `oracle`. Aliases: `pg`, `postgresql`, `sqlite3`, `mssql`, `tsql` e `ora`.
- Sem `-o`, o SQL vai para a saída padrão. Use isso em pipes: `dbml export schema.dbml --dialect mysql | mysql loja`.
- Com `-o`, o comando recusa sobrescrever um arquivo existente. Use `--force` para permitir.

### Mermaid pela CLI

A CLI não tem `--format mermaid`. O Mermaid sai dentro da documentação em Markdown:

```bash
dbml docs schema.dbml --format md -o docs/
```

O `README.md` gerado inclui um bloco `erDiagram`. Veja [Gerar documentação](../guias/gerar-documentacao).

## Notas sobre o SQL gerado

- O cabeçalho do arquivo diz o dialeto: `-- Generated by DB Modeling (postgres)`.
- Enums: `CREATE TYPE ... AS ENUM` no PostgreSQL, `ENUM(...)` na coluna no MySQL e `CHECK (... IN (...))` em SQLite, SQL Server e Oracle.
- Notas: `COMMENT ON` no PostgreSQL e no Oracle, `COMMENT` na tabela e na coluna no MySQL. SQLite e SQL Server não recebem as notas.
- O SQLite não aceita schemas (`auth.users`). A exportação avisa e para.

## Se algo der errado

| Mensagem | Causa provável | O que fazer |
|---|---|---|
| `Revise o DBML antes de exportar SQL: <detalhe>` | O DBML tem erro. | Abra **Problemas** e corrija. |
| `O SQLite não aceita o schema <nome> nesta exportação. Escolha outro dialeto.` | A tabela usa um schema (`auth.users`). | Exporte em outro dialeto, ou tire o schema do nome. Na CLI: ``Error: SQLite export does not support schema `auth` ``. |
| `Escolha outro dialeto para exportar SQL.` | O dialeto escolhido não é suportado. | Use um dos cinco dialetos. |
| `Não foi possível gerar <formato>. Tente exportar em SVG.` (Web) / `Tente exportar em SVG.` (Desktop) | A geração da imagem raster falhou. | Exporte em SVG, que não depende de rasterização. |
| `Não foi possível exportar <formato>. Tente outro nome ou outra pasta.` (Web) | Falha ao gravar. | Use outro nome ou outra pasta. |
| `Falha ao exportar <formato>: <detalhe>` (Desktop) / `Falha ao exportar: <detalhe>` e `Falha ao exportar SQL: <detalhe>` (Web) | Erro genérico. | Veja o detalhe na mensagem. |
| `O arquivo está em uso. Feche-o no outro aplicativo ou exporte com outro nome.` | O arquivo de destino está aberto em outro programa. | Feche-o ou mude o nome. |
| `Sem permissão para gravar neste local. Escolha outra pasta.` | Pasta sem permissão. | Escolha outra pasta. |
| `O disco está cheio. Libere espaço ou escolha outra pasta.` | Sem espaço. | Libere espaço. |
| `Não foi possível abrir a janela de salvamento. Tente exportar novamente.` | O diálogo do sistema não abriu. | Tente de novo. |
| `Error: invalid DBML: <detalhe>` (CLI) | O arquivo `.dbml` tem erro. | Corrija o ponto indicado. |
| `output file ... already exists (pass --force to overwrite)` (CLI) | O destino já existe. | Use `--force` ou outro nome. |
| `error: invalid value 'foo' for '--dialect <DIALECT>'` (CLI) | Dialeto desconhecido. | Use `[possible values: postgres, mysql, sqlite, sqlserver, oracle]`. |
